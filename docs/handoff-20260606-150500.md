## 一、项目是什么

Muye Fusion Gateway — 一个 MCP (Model Context Protocol) 服务端，让 AI 客户端通过标准化接口操控 Fusion 360 进行 CAD 建模。

## 二、当前技术架构（客观描述）

### 2.1 数据流

```
AI 客户端 (WorkBuddy / Claude Desktop / 其他)
    │
    │ MCP JSON-RPC (Streamable HTTP)
    ▼
Muye Fusion Gateway (:8000)
    │ FastMCP 框架, Python 3.13
    │ 37 个已注册工具 (35 领域 + execute_python + capture_viewport)
    │
    │ 自定义 HTTP POST JSON
    ▼
fozzfut/FusionMCP Add-in (:7432)
    │ 运行在 Fusion 360 进程内部
    │
    ▼
Fusion 360 API (内部单位: cm)
```

### 2.2 各层技术细节

| 层 | 技术 | 版本/位置 |
|---|---|---|
| AI 客户端 | MCP 协议客户端 | 任意支持 MCP 的客户端 |
| Gateway | FastMCP (mcp==1.27.2) | `server/` 目录 |
| 上游桥接 | fozzfut/FusionMCP | `~/Library/Application Support/Autodesk/Autodesk Fusion 360/API/AddIns/FusionMCP/` |
| 运行环境 | Homebrew Python 3.13 | `/opt/homebrew/bin/python3.13`, venv 在 `server/.venv/` |

## 五、已知 Bug（客观描述现象和复现条件）

### Bug 1: bridge.py _post() 返回值类型与预期不符

**现象**:
```
[FusionBridge Error] 'str' object has no attribute 'get'
```

**触发条件**:
- 调用 `mass_properties` 工具（生成的 Python 代码约 947 字符）时触发
- 调用简单代码如 `print("hello")` 时不触发（返回 `[OK] no output]`）
- 调用 `create_cube` 等短代码工具不触发（返回 `[OK] no output]`）

**错误发生位置**: `server/bridge.py` 第 97 行 `result.get("success", False)`
- 代码在此行之前已有 `isinstance(result, dict)` 检查（第 90 行新增）
- 但日志显示该检查未拦截到此情况（或日志未被打印）

**已尝试的修复方式及结果**:
1. 在 `_post()` 中将 `json.loads(raw)` 包在 try/except 中 → 未修复
2. 在 `execute_python()` 开头添加 `if not isinstance(result, dict)` sanity check → 日志显示走到此处但仍报错
3. 清理全部 `__pycache__` 并重启 Gateway → 未修复
4. 在 `_post()` 返回前增加 debug 日志打印 type 和 value → 日志确认返回 str

**未尝试的方向**:
- 直接用 curl 调用 FusionMCP :7432 观察 raw response
- 阅读 FusionMCP 源码确认其对不同长度/内容请求的响应格式
- 在 `_post()` 最外层对返回值做 `json.loads()` 二次解析

### Bug 2: print() 输出不被捕获

**现象**:
- 通过 `execute_python` 执行含 `print("hello from fusion")` 的代码
- 返回值为 `[OK] Code executed successfully (no output)`
- print 的内容未出现在 output 字段中

**影响范围**:
- `mass_properties`（依赖 print 输出属性值）
- 任何依赖 stdout 返回结果的工具
- 不影响只做创建操作的工具（create_cube 等，它们不需要返回文本输出）

### Bug 3: capture_viewport 原生命令不存在（已绕过）

**现象**: 调用 `capture_viewport` 时 FusionMCP 返回 `Unknown command 'capture_viewport'`

**当前状态**: 已改为通过 `execute_python` 内联实现（调用 `viewport.saveAsScreenshot()`）。是否能在 Fusion 360 中正常截屏尚未验证。

## 六、Fusion 360 API 客观事实记录

以下是从 34 个 Codebook 脚本测试中观察到的 API 行为。这些是实测结果，不是推测。

### 6.1 属性名

| 调用方式 | Fusion 360 实际行为 |
|---|---|
| `design.rootComponents` | ❌ 抛出 AttributeError。正确写法: `rootComponent`（单数）|
| `body.bodies` | ❌ 不存在。正确写法: `bRepBodies` |
| `sketch.lines` | ❌ 不存在。正确路径: `sketch.sketchCurves.sketchLines` |
| `design.name` | ❌ Design 对象无 name 属性 |

### 6.2 方法调用

| 调用方式 | Fusion 360 实际行为 |
|---|---|
| `rootComp.addNewComponent(None)` | ❌ 报 invalid argument transform。需传 `Matrix3D.create()` |
| `JointGeometry.create(point)` | ❌ 不是静态方法。正确: `JointGeometry.createByPoint(vertex)` |
| `motion.setAsRevoluteJointMotion(Vector3D.create(...))` | ❌ 失败。需传入枚举如 `JointDirections.ZAxisJointDirection` |
| `rootComp.contactSets` | ❌ rootComponent 无此属性。正确: `design.contactSets` |
| `contactSets.add(ObjectCollection.withItems([...]))` | ❌ 失败。接受 Python list: `contactSets.add([occ1, occ2])` |
| 使用 `DocumentTypes.FusionAssemblyDocumentType` | ❌ 不存在。正确: `FusionDesignDocumentType` |
| 用 `RevolveFeatures` 做圆环 (Torus) | ❌ 报 ASM_PATH_TANGENT。改用 `SweepFeatures` 可成功 |

### 6.3 单位

- Fusion 360 Python API **内部统一使用厘米 (cm)**
- 用户通常提供毫米 (mm) 参数
- 转换关系: `api_value = user_mm_value / 10.0`

### 6.4 几何体构建特殊方法

| 形体 | 方法 | 关键参数 |
|---|---|---|
| 球体 (Sphere) | RevolveFeatures: 半圆绕直径转 360° | YZ 平面画半圆 |
| 圆锥 (Cone) | RevolveFeatures: 直角三角形绕直角边转 360° | YZ 平面画三角形，轴 = Y 轴线段 |
| 圆环 (Torus) | SweepFeatures: 小圆沿大圆扫掠 | Path = XY 平面大圆, Profile = XZ 平面小圆 |
